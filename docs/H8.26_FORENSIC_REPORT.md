## Code-level gates closed in H8.26

- Durable idempotency is resolved from fresh persisted rows; cache entries are
  hints only. Duplicate persisted identities, stale cache pointers, fresh
  process retries, payload conflicts, and deterministic `Payment_ID` collisions
  fail closed.
- Self-service persistence requires a fresh read proving `Payment_Type`, both
  idempotency fields, actor identity, and deterministic payment identity.
- Finance/Admin/Master authorization is enforced in payment, invoice,
  transaction, and account mutation services, with role lookup from the SSOT
  when only `Role_ID` is present.
- Notification reminder lookup requires durable reference columns and fresh
  reads; URL callers preserve `Action_URL` into the production `Link` field.
- Invoice canonical line items and all finance-domain writes are schema-gated;
  no compatibility path silently discards financial fields.
